# Чернильник v0.6

Личный Telegram-бот для литературных ролевых игр.

Текст генерируется через **Polza API** (по умолчанию `google/gemini-3.7-flash`), память и анализ фото — через **OpenAI**. Стек: Python 3.11+, aiogram 3, SQLite.

## Возможности

- **Миры** — канон, энциклопедия, глобальная хроника событий.
- **Истории** — отдельные сюжеты внутри мира (или свободные без мира): свои ходы, время, локация, факты.
- **Персонажи** — общие карточки мира с ролью «игрок / бот / NPC» в каждой истории; анкета из 16 необязательных полей и фото.
- **Память** — факты текущей истории, поиск старых ходов, осторожное извлечение мировых событий и наблюдений за героями.
- **Интерфейс** — кнопочная навигация, пагинация списков, индикатор «печатает…» во время генерации.

## Быстрый старт (локально)

```bash
pip install -r requirements.txt
cp .env.example .env   # или создай .env вручную
python bot.py
```

Минимальный `.env`:

```env
BOT_TOKEN=
OWNER_TELEGRAM_ID=
OPENAI_API_KEY=
POLZA_API_KEY=
DATABASE_PATH=./data/roleplay.sqlite3
ALLOW_NEW_DATABASE=true
```

`ALLOW_NEW_DATABASE=true` нужен только при **первом** создании пустой базы. После старта флаг лучше убрать.

## Деплой на BotHost Pro

1. Залей репозиторий в корень проекта (рядом с `bot.py` должны быть `worlds.py`, `world_ui.py`, `typing_status.py` и остальные модули).
2. Точка входа: `bot.py` (см. `bothost.json`).
3. Переменные окружения:

| Переменная | Обязательно | Описание |
|---|---|---|
| `BOT_TOKEN` | да | токен от BotFather |
| `OWNER_TELEGRAM_ID` | да | числовой Telegram ID владельца |
| `OPENAI_API_KEY` | да | память и vision |
| `POLZA_API_KEY` | да | генерация текста |
| `DATABASE_PATH` | да | `/app/data/roleplay.sqlite3` |
| `MEDIA_DIR` | нет | `/app/data/portraits` |
| `MEMORY_MODEL` | нет | по умолчанию `gpt-6-luna` |
| `VISION_MODEL` | нет | по умолчанию `gpt-6-luna` |
| `GENERATION_PROVIDER` | нет | `polza` |
| `GENERATION_MODEL` | нет | `google/gemini-3.7-flash` |
| `POLZA_BASE_URL` | нет | `https://polza.ai/api/v1` |
| `AUTO_MEMORY` | нет | `true` |
| `MAX_OUTPUT_TOKENS` | нет | `1800` |
| `ALLOW_NEW_DATABASE` | нет | только для новой пустой БД |

4. Каталог `/app/data` должен быть постоянным. Не удаляй его при обновлениях.
5. Не коммить `.env`, ключи и SQLite в Git.

### Обновление с предыдущей версии

1. В Telegram: `/backup` — скачай базу. При необходимости сохрани `/app/data/portraits`.
2. Обнови код в том же проекте BotHost, не создавая нового бота.
3. Сохрани прежние переменные окружения; путь `DATABASE_PATH` не меняй.
4. Перезапусти. Схема SQLite расширяется автоматически, старые истории не стираются.
5. Проверка: `/start` → **📚 Миры** → создай мир и историю → **✒️ Начать**.

Если нужна чистая тестовая база — укажи **другой** путь (например `/app/data/chernilnik_test.sqlite3`) и один раз `ALLOW_NEW_DATABASE=true`. Старый файл не удаляй.

Если BotHost пишет `ModuleNotFoundError` для `worlds` / `world_ui` / `typing_status` — в репозиторий залита не вся папка проекта.

## Telegram

Главное меню `/start`: **📚 Миры**, **📖 Истории**, **👤 Персонажи**, **🗂 Меню**, **✒️ Начать**.

Команды: `/worlds`, `/model`, `/begin`, `/sessions`, `/backup`, `/prompt`, `/export`, `/last`, `/draft`, `/play`, `/cancel`, `/status`, `/help`.

Во время генерации бот шлёт Telegram-статус «печатает…» примерно раз в 4 секунды. Фиктивных сообщений нет.

## Ограничения

- Автопамять пополняет анкету и хронику по сыгранным постам — это не полный психологический профиль с нуля. Предположения отделены от фактов.
- Глобальные события мира извлекаются LLM и могут ошибаться; иногда сверяй **Миры → События**.
- Разграничение знаний между NPC — через промпты, без жёстких ACL в БД.
- `/backup` сохраняет SQLite; портреты лежат отдельно в `MEDIA_DIR`.
- При потере базы см. [`DB_RECOVERY.md`](DB_RECOVERY.md).
