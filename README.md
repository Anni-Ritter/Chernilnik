# Личный литературный Telegram-соавтор (MVP 0.3)

**Статус:** исполняемый прототип для локального запуска. Живой запрос к OpenAI и Telegram не проверялся — нужны твои собственные API-ключи. Автопамять не гарантирует абсолютной непротиворечивости.

## Старт

1. Создай нового бота через [@BotFather](https://t.me/BotFather), возьми токен.
2. Уточни свой числовой Telegram ID (например, в сервисном боте, который показывает ID; либо временно запусти с любым числом и напиши /id своему боту).
3. Установи Python 3.11+.
4. В папке проекта создай `.env`, скопировав `.env.example`, вставь `BOT_TOKEN`, `OPENAI_API_KEY`, `OWNER_TELEGRAM_ID`.
5. Установи зависимости и запусти:

   ```bash
   python -m venv .venv
   # Windows: .venv\Scripts\activate
   # Linux/macOS: source .venv/bin/activate
   pip install -r requirements.txt
   python bot.py
   ```
6. Открой личный диалог с ботом в Telegram. `/start`, `/new История`, `/cast Я играю за ..., бот за ...`, и нажми **«Начать историю»** или введи `/begin`. Бот напишет первый пост сам.

## Долговременная память

- Полная история каждого хода навсегда сохраняется в локальной SQLite (`roleplay.sqlite3`), пока ты сама не удалишь БД. Сделай резервные копии файла.
- На каждом ходе модель видит последние 8 ходов, зафиксированное описание мира, роли, время, локацию и выборку важных фактов. Полная история **не** отправляется целиком в каждом запросе.
- Дополнительный вызов модели извлекает до 6 атомарных фактов с дословными свидетельствами в только что сыгранном ходе. Без точной цитаты автоматический факт не сохраняется. Выборка не сохраняет очевидный декоративный мусор (приоритеты ниже 3) и отделяет субъективные догадки от подтверждённых сведений.
- Факты с важностью 5 доступны глобально в пределах истории, остальные подтягиваются по пересечению ключевых слов. Это **упрощённая лексическая выдача**, без эмбеддингов/векторного поиска. Если важнейших фактов накапливается больше доступного бюджета контекста, некоторые из них тоже могут не попасть в конкретный запрос.
- `/remember` — вручную закрепить критический факт 5/5. `/memory` — проверить, что запомнено. Автоматическое извлечение может ошибаться: проверяй ключевые события.
- `/time` хранит текстовую временную опору. **Бот не отсчитывает дни и месяцы автоматически**: 10 постов не равны 10 дням. Для временных прыжков явно обозначай их в постах и обновляй `/time`. Полноценный фэнтезийный календарь пока не реализован.
- Все миры независимы — факты не мигрируют между сессиями.

## Важные ограничения первой версии

- Нет перегенерации, выбора ответов и кнопки подтверждения. Успешный ответ сразу записывается как очередной ход.
- Нет защиты от стопроцентных логических ошибок, перехвата персонажей и путаницы имён — пока это инструкции, а не гарантии. Сложный граф событий и строгая проверка канона — следующие этапы.
- Код не проверялся на реальном API (ключей нет), поэтому при несовместимости модели поправь `OPENAI_MODEL`/`MEMORY_MODEL`.
- Модельный вызов памяти добавляет цену к каждому ходу. `AUTO_MEMORY=false` отключает автопамять (ручные `/remember` продолжают работать).
- Указан `store=False` в OpenAI API, но запросы всё равно обрабатываются провайдером; изучи его условия хранения и приватности.
- Локальная БД не зашифрована. Не публикуй её и не коммить `.env` в Git.
- В `/status` отдельно учитываются токены генерации и памяти. Текущей долларовой оценки расходов пока нет.
- Подход к темам для взрослых определяется также ограничениями модели/провайдера; программно снять их нельзя.

## Управление

`/help` — список команд. `/draft` + сообщения + `/play` для поста длиннее лимита Telegram. `/export` отправит весь текст текущей истории как `.md`. `/last` повторно покажет последний сгенерированный ответ, если произошёл сбой отправки: **это не перегенерация**.

## Тесты

```bash
pytest -q
```

При тестах ни OpenAI, ни Telegram не вызываются. Проверяются SQLite, изоляция историй, выбор воспоминаний и фильтр свидетельств.


## Новое в v0.2: бот начинает первым

После `/new` настрой `/cast` и, если нужно, `/world`, `/time`, `/location`. Нажми кнопку **«Начать историю»** или напиши `/begin`. Бот самостоятельно создаст стартовый художественный пост и запишет его в таблицу `openings` (отдельно от обычных пар ходов). Первый пользовательский пост не требуется. `/opening` безопасно повторно показывает его без генерации.

В одной истории может быть только один первый пост. Повторные `/begin` не генерируют новый текст. В существующих историях, где уже начаты ходы, `/begin` не создаёт альтернативное начало. При обновлении на Bothost **не удаляй `/app/data/roleplay.sqlite3`** — новая таблица создаётся автоматически без удаления истории.


## Новое в v0.3: кнопочный Telegram-интерфейс и внешность по фото

1. Открой бот и отправь `/start` **один раз после обновления**. В нижней клавиатуре появятся `🗂 Меню`, `📖 Истории`, `👤 Персонажи`, `✒️ Начать`. Дальше команды не нужны — меню и подменю работают кнопками.
2. `📖 Истории` → `➕ Новая история`: напиши название, затем открой `👤 Персонажи` → `➕ Новый персонаж`; введи имя и выбери, кто его отыгрывает (`ты`, `бот`, `NPC`).
3. В карточке персонажа доступны: биография/характер, ручное описание внешности, роль, смена имени, удаление, до пяти фото. `➕ Фото` → отправь JPG/PNG/WEBP **как фотографию или документ**. Файл сохраняется в `MEDIA_DIR`, после чего модель один раз анализирует видимые признаки и записывает их как описание. Анализ можно повторить; фото — посмотреть, сделать основным или удалить.
4. Меню `🌍 Мир и сцена` → кнопки для канона, ролей, времени, локации. `🧠 Память` → факты и закрепление важного. `✒️ Первый пост` → бот открывает историю самостоятельно, без перегенераций.
5. Для длинных постов выбери `📝 Длинный пост`. Присылай части и нажми нижнюю кнопку `📨 Отправить пост` или `❌ Отменить черновик`.

Оригиналы фото сохраняются на диске (или сжатые Telegram-копии при отправке обычным фото), а в контекст литературной модели каждый ход передаются **текстовые описания**, не повторные изображения. Это снижает стоимость. Ручное описание внешности имеет более высокий приоритет, чем автоматическое. Фото и карточки относятся к одной истории. Познание внешности не означает, что герои знают чужие тайны. Не все свойства по фото можно определить достоверно; исправляй спорные детали через кнопку `✏️ Уточнить внешность`.

### Новые переменные окружения

- `VISION_MODEL=gpt-6-luna` — дешёвая модель OpenAI, принимающая изображения. Можно оставить значение по умолчанию; отдельный ключ не нужен.
- `MEDIA_DIR=/app/data/portraits` — каталог оригиналов фото; по умолчанию создаётся рядом с `DATABASE_PATH`.

Важно: для Bothost Pro нужны **обе** постоянные папки: `/app/data/roleplay.sqlite3` и `/app/data/portraits/`. База содержит записи и описания, фотографии — отдельные файлы. При деплое они не должны исчезать. Для резервного копирования сохраняй всю `/app/data`, а не только sqlite-файл. Экспорт Markdown включает тексты и описания фото, но **не** сами файлы изображений.

**Пределы и тестирование:** для доступа к фото Telegram Bot API имеет лимит скачивания до 20 МБ; в боте для контроля расходов и ресурсов установлен более строгий предел **12 МБ**. Максимум **5 фото на героя**; в генерацию попадают основной подробный и остальные сокращённые описания. Неизвестные файлы не принимаются. `pytest -q` проверяет БД и обработку изображений офлайн. Живой запуск Telegram UI + OpenAI Vision в этой среде не проверен (нет API-ключей и установленного aiogram); проверь один референс после деплоя.
